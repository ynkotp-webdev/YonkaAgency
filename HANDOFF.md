должен быть достаточен, чтобы следующий агент спроектировал по нему sitemap, IA, homepage,
service pages, UX, UI, SEO-архитектуру, conversion funnel, design system и техническую архитектуру
**без повторного исследования конкурентов**.

## 4.2. Ключ Google PageSpeed Insights API (нужен)

Анонимная квота PSI закрыта — получено **HTTP 429 на всех 12 запросах** (6 сайтов × mobile/desktop).
Бесплатный ключ даёт ~25 000 запросов/сутки и открывает сразу:

- **Lab data** — Lighthouse mobile + desktop (LCP, FCP, TBT, CLS, Speed Index, вес ресурсов)
- **Field data** — CrUX по реальным пользователям за 28 дней (LCP, INP, CLS, TTFB)

Получить: Google Cloud Console → включить «PageSpeed Insights API» → создать API key.

Запрос с ключом:
```
https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=<URL>&strategy=mobile&key=<KEY>&category=performance&category=accessibility&category=best-practices&category=seo
```

**Без ключа Core Web Vitals остаются `Not verified`** — выдумывать их запрещено брифом.

Частичный обходной путь без ключа: скачать все CSS/JS/изображения из HTML и посчитать
суммарный вес и число запросов. Даст page weight и разбивку по типам, но не даст CWV.

## 5.1. ГЛАВНЫЙ СТРАТЕГИЧЕСКИЙ ВЫВОД

**Топ-6 украинской выдачи по коммерческому запросу «сайт під ключ» — слабая.**

Учитывая, что это именно первые шесть результатов Google (§2), а не отобранные по качеству сайты:

- На позиции в топ-6 стоит сайт (**ISDL**) с **418 словами** на коммерческой странице,
  **без robots.txt**, **без sitemap**, **без schema**, **без Open Graph**, с
  **краулинговой ловушкой** и полифилами для **Internet Explorer 8**.
- Ещё один (**Fabryka**) — **23 URL всего**, без canonical, без OG, без schema,
  28 из 38 изображений без `alt`, **ноль форм** на коммерческой странице.
- Только **один из шести** (SEOK) имеет зрелую техническую реализацию.
- **Четыре из шести** не имеют ни одного security-заголовка.
- **Три из шести** не имеют `<main>`; **два** не имеют ни `<header>`, ни `<footer>`.

**Следствие для стратегии:** порог входа в топ низкий. Технически грамотный, быстрый,
семантически размеченный сайт с проработанной архитектурой способен конкурировать за топ
не за счёт бюджета на ссылки, а за счёт качества исполнения. Это надо заложить в стратегию как
основную ставку.

**Оговорка:** позиции не подтверждены инструментально (§4.3), утверждение опирается на
слова пользователя о том, как он собирал список. Проверить в Playwright до финальных выводов.

## 5.2. SEOK — единственный сильный референс

`https://seok.ua/uk/sozdanie-sajtov`

Опережает остальных практически по всем измеримым техническим параметрам:

- **Security:** единственный с полным CSP + HSTS `preload` + `nosniff` + Referrer-Policy + Permissions-Policy
- **hreflang:** единственный с корректным `x-default` (`uk-UA` / `ru-UA` / `x-default`)
- **Schema:** единственный, кто размечает **цену** (`Offer`, `AggregateOffer`, `PriceSpecification`)
  и **автора** (`Person`) — шанс на расширенные сниппеты + сигнал E-E-A-T
- **Изображения:** 201 шт., **0 без alt**, 161 с `loading="lazy"`
- **Семантика:** ровно один `header` / `nav` / `main` / `footer` — единственный корректный из шести
- **Формы:** `label` = `input` (15 = 15)
- **Контакты:** 6 ссылок `tel:`, 3 `mailto:`

### 5.2.1. Его CSP выдал весь конверсионный стек

Content-Security-Policy перечисляет разрешённые хосты и тем самым раскрывает инфраструктуру:

| Слой | Сервис |
|------|--------|
| Коллтрекинг | **Binotel** |
| CRM | **KeyCRM** |
| Мгновенные уведомления | **Telegram Bot API** |
| Аналитика | GA4, GTM, Microsoft Clarity, Yandex Metrica |
| Реклама | Google Ads, DoubleClick, Meta Pixel |
| Админка | `cms.seok.ua` (headless/раздельная) |

Это **сквозной lead-tracking**: звонок → источник → CRM → уведомление. Ни у кого из остальных
пяти подобного стека не обнаружено. Это прямое подтверждение того, что сайт построен вокруг
измеримой лидогенерации, а не вокруг презентации.

### 5.2.2. Его description — единственный написанный как оффер

```
Сайт під ключ, який приносить заявки, а не просто гарно виглядає.
Видно, звідки прийшов клієнт: пошук, реклама чи соцмережі.
Сума в договорі не змінюється.
```

155 символов, **три обработанных возражения**, ноль эмодзи:
«красиво ≠ эффективно» → «непонятно, откуда лиды» → «смета вырастет».

Для сравнения, Brainlab на том же месте: `✅ Високі вимоги до якості ⚡ Оперативність ➔ Прозорість роботи ⭐ Доступна вартість ☎️`
— набор абстракций и символов-«украшений».

**Это забрать в свой сайт обязательно.**

### 5.2.3. Но архитектура у него спорная

- **Плоская структура:** 162 уникальных корневых слага, всё в `/uk/<slug>`, папки `/services/` нет.
- Коммерческие страницы и блог **в одном пространстве имён**, блог отличается только суффиксом `.html`
  (`/uk/dizajn-sajta` — услуга, `/uk/chto-takoe-seo.html` — статья). Легаси.
- **Слаги русской транслитерацией на украинской версии**: `/uk/sozdanie-sajtov`, `/uk/cena-sozdaniya-sajta`.
  Несогласованность языка URL и языка контента.
- Title 88 символов — обрежется в выдаче.
- H3/H4 не используются вообще (только H2) — плоская иерархия заголовков.

**Брать модель «одна страница на один интент», но не брать плоские URL и не смешивать блог с услугами.**

| Ноль форм и ноль `tel:`/`mailto:` на целевой странице | — |

### Fabryka (`fabryka.cc`) — Joomla, микро-сайт

- **Нет canonical**, нет OG, нет Twitter Card, нет JSON-LD, нет hreflang
- **28 из 38 изображений без `alt`** (74%)
- Нулевой lazy-loading
- **Ноль `<form>`** на коммерческой странице — только 2 ссылки `tel:`
- Устаревшая директива `Host:` в robots.txt
- HSTS `max-age=300` — 5 минут, символическое значение
- H1 `Розробка сайтів (сайту) Львів` — скобки выдают keyword stuffing
- 984 слова

### SEO-Design (`seo-design.ua`) — провал доступности и контакта

- **Ноль `<label>`** при 3 инпутах
- **Ноль `tel:` и ноль `mailto:`** в HTML — позвонить с мобильного в один тап нельзя
- **Ноль `<header>`, `<main>`, `<footer>`** — вёрстка на `div`, скринридеру не за что зацепиться
- **73 `<script>`** — самый тяжёлый по JS
- Из schema только `Organization`
- robots.txt блокирует `ia_archiver` (**web.archive.org**) + Semrush, Moz, Serpstat, Ahrefs-подобных
- Устаревшая директива `Host:` → robots.txt не пересматривался годами

### Webnauts — технический долг под развитой архитектурой

- **38 отдельных CSS-файлов** — бандлинга нет, классический непооптимизированный WordPress,
  прямой удар по render-blocking и FCP
- **2 тега `<main>`** — нарушение спецификации HTML
- **10 тегов `<header>`**
- В продакшн-HTML остались **закомментированные блоки разметки с `<h1>` внутри** — мёртвый код едет в прод

### Brainlab — изображения

- **19 изображений без `alt`**, **нулевой `loading="lazy"` при 73 картинках** — риск для LCP
- Из schema только `BreadcrumbList`
- Ноль `tel:` при 10 `mailto:`
- ✅ но при этом **1 CSS-файл** на 12 секций — лучшая сборка стилей из шести

## Контекст

Твоя задача — провести глубокое исследование шести сильных и релевантных сайтов веб-студий / агентств по разработке сайтов, которые находятся в верхней части органической поисковой выдачи по целевым коммерческим запросам. Эти сайты являются объектами конкурентного исследования и не должны восприниматься как шаблоны для копирования. Цель исследования — понять, какие решения используют сильные игроки рынка, какие из них действительно эффективны, какие имеют недостатки и какие выводы можно применить при создании нового сайта моей веб-студии.

Ты должен использовать доступные браузерные инструменты, прежде всего Playwright MCP, Chrome MCP или другие подключённые browser automation / web research инструменты, чтобы непосредственно посещать сайты, взаимодействовать с ними и проверять их реальное поведение. Не ограничивайся поисковыми сниппетами, исходными страницами поисковой выдачи или поверхностным визуальным просмотром. Исследование должно основываться на фактическом изучении самих сайтов.

Твоя задача состоит не в том, чтобы просто описать эти сайты, а в том, чтобы провести системный конкурентный аудит и извлечь из него практические архитектурные, UX, SEO, UI и conversion-инсайты для будущего сайта.

# 1. Выбор сайтов

Сначала определи шесть наиболее релевантных сайтов веб-студий / digital agencies / website development studios из органической выдачи.

При выборе сайтов учитывай:

* коммерческую релевантность;
* качество самого сайта;
* соответствие нише;
* современность решения;
* наличие полноценного коммерческого сайта;
* наличие развитой структуры;
* потенциальную ценность сайта как reference implementation.

Не включай в исследование:

* агрегаторы;
* каталоги;
* шаблонные landing pages низкого качества;
* статьи;
* Wikipedia;
* социальные сети;
* сайты, которые не являются непосредственно конкурентами или близкими по бизнес-модели.

Зафиксируй для каждого выбранного сайта:

* URL;
* название компании;
* поисковый запрос, по которому он найден;
* позицию в выдаче;
* тип компании;
* основные услуги;
* краткое объяснение, почему этот сайт включён в исследование.

# 2. Методология исследования

Каждый из шести сайтов должен быть исследован по одинаковой методологии.

Не оценивай сайты исключительно субъективно.

Для каждого важного вывода:

1. найди конкретное наблюдение;
2. зафиксируй evidence;
3. объясни, почему это важно;
4. определи потенциальное влияние;
5. только после этого делай оценку.

Разделяй:

**Fact → Observation → Interpretation → Recommendation.**

Например:

**Fact:** на главной странице CTA "Request a Quote" находится в header и повторяется после каждого основного service section.

**Observation:** компания систематически поддерживает возможность перехода к conversion action.

**Interpretation:** CTA является частью основного user journey, а не вторичным элементом.

**Recommendation:** рассмотреть аналогичную CTA-архитектуру для собственного сайта.

Не выдавай субъективное впечатление за объективный факт.

Ты не должен создавать сайт во время этого этапа исследования.

* homepage;
* service pages;
* content hierarchy;
* UX;
* UI;
* SEO architecture;
* conversion funnel;
* design system;
* technical architecture.

Все существенные рекомендации должны иметь связь с исследованными конкурентами и конкретными evidence.

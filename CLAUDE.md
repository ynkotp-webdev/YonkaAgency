# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Команди

```
npm run dev       # astro dev — локально на http://localhost:4321/
npm run build     # статична збірка в dist/
npm run preview   # прев'ю зібраного
```

Тестів і лінтера немає. Перевірка = `npm run build` (падає на помилках схеми контенту й
типів) + очима в браузері. Деплой автоматичний: push у `main` → `.github/workflows/deploy.yml`
(`withastro/action`) → GitHub Pages на власному домені `yonkaagency.com.ua`
(файл `public/CNAME`).

## Що це

Комерційний сайт веб-студії однієї людини (Остап Йонка, Львів). Astro 5 + Tailwind 4
(через `@tailwindcss/vite`, без `astro add tailwind`), статика на GitHub Pages,
без бекенду й без JS-фреймворків. Контакт — прямі `tel:` і Telegram, форми немає.

Сайт українською. Російська версія (`/ru/`) передбачена в `Base.astro`, але **не збудована** —
перемикач мов і `hreflang="ru"` навмисно прибрані, щоб не вести в 404.

## Базовий шлях

Сайт живе в корені власного домену: `astro.config.mjs` задає `site: 'https://yonkaagency.com.ua'`
і `base: '/'`. Внутрішні посилання все одно будуються від
`import.meta.env.BASE_URL.replace(/\/$/, '')` — так заведено, щоб повернення на підшлях
не ламало сайт. Нові посилання писати так само.

CSS не бачить `BASE_URL`, тому в [global.css](src/styles/global.css) шляхи до шрифтів
захардкоджені як `/fonts/…` (позначено `ponytail:` коментарем). Якщо `base` колись зміниться,
міняти обидва місця: `base` в конфігу й `@font-face` у CSS.

  сусідніх селекторах, **без скрипта** — не переписувати на JS).

## Колекція `roboty`

Схема — [src/content.config.ts](src/content.config.ts), файли — `src/content/roboty/*.md`,
картинки — `src/assets/roboty/*.webp` (оптимізує `astro:assets`). Додати роботу = додати
один `.md`.

Схема навмисно жорстка, і це змістове, а не технічне обмеження:

- `status`: `concept` | `draft` | `demo` | `client`. Реальних клієнтів поки немає —
  `client` не використовувати, поки замовлення справді не здане.
- `.refine()` забороняє `before` без `sourceUrl`: знімок «було» мусить вести на реальний
  чинний сайт, інакше це вигадка.
- `metrics` обов'язкові — саме заміри, а не картинка, є доказом рівня. `before` в метриці
  необов'язковий (для робіт з нуля порівнювати нема з чим).
- `tradeoffs` — те, чого робота не закриває. Блок чесності на сторінці; не прибирати.

## Дизайн-система

Повний опис — [DESIGN.md](DESIGN.md), обов'язкові заборони — [research/26-anti-slop-brief.md](research/26-anti-slop-brief.md)
(binding). Коротко, бо це порушується найчастіше:

- Світ «схема маршруту»: папір `#f6f6f4`, чорнило `#14121a`, фіолетовий `route #5b21b6`,
  бліда лінія `detour`. Токени в `@theme` у [global.css](src/styles/global.css).
- **Ніяких сіток однакових карток**, ніяких тіней, скла, градієнтів. Глибина — тільки
  тон (`paper` → `paper-deep` → `route-deep`), лінія і повна інверсія секції.
- Дефолти Tailwind перевизначені навмисно: не повертати `rounded-lg`, `shadow-md`,
  `max-w-7xl`, `container`. Радіусів рівно два: `3px` (плашка) і `999px` (вузол схеми).
- Немає структури Hero → Features → Testimonials → CTA і немає кікера над заголовком.
  Нова секція збирається з чотирьох іменованих пристроїв (DESIGN.md §Components),
  а не з нових карток.
- Geologica — голос, JetBrains Mono (`.notation`) — тільки заміри й підписи схеми.

## Жорсткі вимоги, які не можна спрощувати

Доступність тут — частина продажу (дослідження показало, що конкуренти її провалюють),
тому: контраст ≥ 4,5:1, видимий фокус-ринг (`outline: 2px solid route` — знімати
заборонено), інтерактив ≥ 44×44 px і кнопки 52px заввишки, зум не блокувати,
рівно один `header`/`main`/`footer`/`h1`.

Бюджет: мобільний LCP ≤ 2,5 с, вага сторінки ≤ 1500 КБ. Увесь рух — усередині
`@media (prefers-reduced-motion: no-preference)`, геометрія SVG повна вже в розмітці
(схема мусить бути на місці при вимкненій анімації, друку й у t=0).

## Правда в текстах

Клієнтів, відгуків, рейтингів і кейсів з результатами клієнта **немає** — вигадувати
заборонено (див. [PRODUCT.md](PRODUCT.md) §Evidence on Hand). Формулювання «проєкти, які
ми реалізували для наших клієнтів» заборонені. Обіцяти можна лише те, що виконується:
строк, фіксовану суму в договорі, прямий контакт, адмінку у вартості (Pages CMS, вхід
за кодом із пошти; клієнт сам змінює те, що винесено у форму: ціни, послуги, фото, команду),
домен і хостинг на клієнта. Постійного обслуговування після запуску немає — так і написано
на сайті: дизайн, нові розділи й усе поза адмінкою — через мене, окремо. Писати, що ціни
чи фото можна змінити «тільки через мене», не можна: з 10.11.2026 це неправда.

## Мова сайту — бізнесова, не інженерна

Читач сайту — власник салону, клініки, магазину. Він не купує мілісекунди й
кілобайти, він купує заявки. Тому в текстах, які він бачить (сторінки робіт,
заміри, головна), технічний жаргон заборонений: без «JavaScript», «КБ», «LCP»,
«CLS», «lazy-loading», «мікророзмітки», «canonical», «тегів header/footer»,
назв технологій і показників, які самі по собі нічого йому не кажуть.

Кожен технічний факт перекладається ланцюжком **що відбувається → що бачить
відвідувач → що це коштує бізнесу → як це виправити**:

- ❌ «Багато JavaScript, через що росте обсяг завантаження».
- ✅ «Сторінка вантажиться довше, і клієнтка закриває її, не побачивши цін».

Технічний факт лишається в тексті лише тоді, коли він доводить конкретну втрату.
Не доводить — прибрати. Питання до кожного рядка: **чому власнику бізнесу це має
бути важливо?**

Це стосується й `metrics` у колекції `roboty`: підпис заміру формулюється
людською мовою («Скільки клієнтка чекає перший екран»), а не назвою метрики
(«LCP»). Заміри лишаються справжніми — змінюється тільки те, як вони названі.

Внутрішня документація (`CLAUDE.md`, `DESIGN.md`, коментарі в коді) — навпаки,
технічна, і спрощувати її не треба.
